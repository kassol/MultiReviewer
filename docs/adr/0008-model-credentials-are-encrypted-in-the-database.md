# 模型凭据加密存库,主密钥留在环境变量

> 2026-08-20: 加密、只写不回显与子进程隔离继续有效；凭据的独立保存与验证生命周期由 ADR 0010 取代。

面板要成为唯一的配置面,模型凭据因此从 `.env` 的一组厂商变量搬进数据库,由面板写入。同一个库里的仓库 Key 是**明文**存的,理由写在 `src/review/store.ts` 的建表注释里:HMAC 验签需要原始值。模型凭据没有这条约束——它只需要在组装 Reviewer 时还原成明文,中间怎么存是自由的。这里选择加密。

主密钥从环境变量来。这没有消除环境变量,只是把 N 个厂商变量换成 1 个主密钥变量;换来的是数据库文件本身不再是一份可直接读取的凭据清单。备份、误传、快照复制这类数据库离开原机的场景,是这个选择实际防住的东西。

解不开的密文视为未配置。主密钥丢失或更换后不做重加密迁移:面板在凭据页显示该 provider 未配置,人重新粘一次 key 即可。单人部署下,重新粘两把 key 比维护一条只在故障时才跑的轮转路径便宜得多。

## Considered Options

- **明文存库,与 Key 同构。**形态最一致,也最好解释。否决的原因是它让数据库变成一份完整的、可直接使用的厂商凭据清单——而 Key 明文是密码学逼出来的,模型凭据没有这个逼迫,拿它当先例是把一条约束当成了一种风格。
- **主密钥交给外部密钥管理服务。**部署形态是单机 compose,引入 KMS 会让部署多一个必须先可用的外部依赖,而防住的攻击面与环境变量主密钥几乎相同。
- **主密钥轮换命令(旧密钥解、新密钥重加密)。**多一条只在故障时才跑、因而最不容易被测到的代码路径,换来的是省下人工重粘两把 key。不值。

## Consequences

- **凭据按 provider 存一份**,表形如 `model_credential(provider, api_key_encrypted, updated_at)`。同一家下的多个 model 共用一把,轮转只改一处。
- **`ReviewerSpec` 去掉 `apiKeyEnv`**,只剩 `provider` 与 `model`,凭据由 provider 查库得到。保留双轨会立刻产生「文件与库谁赢」——「模型覆盖」当初刻意避开的正是这个。
- **服务启动不再校验凭据。**`buildReviewers` 现在缺一个变量就抛,服务起不来;配凭据的地方变成面板之后,这条会让空库的新部署锁死自己——起不来就进不了面板,进不了面板就配不了凭据。校验挪到投递到达、组装 Reviewer 的时刻,缺凭据的 provider 让那次 Review Run 失败并在时间线上写明缺哪一家。
- **面板保存凭据时真发一次最小请求验证,失败不保存。**快失败的价值从启动时转移到这里。不验的话,key 打错要等下一个 PR 进来才暴露。
- **凭据只写不回显。**列表显示 provider、是否已配、更新时间、尾 4 位。Key 需要回显是因为人要抄去 Gitea 装 hook,模型凭据没有对应用途。
- **主密钥缺失时凭据页整体不可用**,读写都做不了,面板提示先设置主密钥环境变量。这与「启动放行」不冲突:服务照常起,只是这一页告诉人差什么。
- **解密在编排进程完成**,子进程的注入路径不变——仍是 `MULTIREVIEWER_MODEL_API_KEY` 单变量,`reviewerEnv` 仍先剥光父进程环境(ADR 0004)。密文与主密钥都不进子进程。
- **凭据在 Review Run 开始时快照,跑中不重读。**轮转对进行中的 Run 无影响,下一次投递自然用新的,不需要中断或迁移逻辑。
- **本 ADR 不动 ADR 0005。**那条管的是 Forge 凭据(Gitea bot PAT / GitHub App),仍在 `.env`,与模型凭据是两类东西。
