# Reviewer 之外的 agent 共用一处辅助模型,选模型的地方只剩审查策略与仓库配置

此前选模型散在五处:审查策略页的全局模型组合、仓库配置的模型覆盖、知识集弹窗里基点探索与知识整理各自的发起表单,以及两条没有界面的隐式规则——合并 agent 取配置序第一个 Reviewer,处置反哺与人工提议取这个仓库最近一次基点探索的模型、没探索过再取全局组合第一个。同一件事(agent 用哪个模型)由五套取法决定,人要在四个地方分别记住它们,反哺的模型还悄悄跟着上一次探索走。

选定的做法:**审查策略里开一处「辅助模型」引用(模型标识加思考档位),Reviewer 之外的全部 agent 工作都用它**——合并 agent、基点探索、知识整理、处置反哺、人工提议。仓库配置可以用自己的一处替换,与模型覆盖、最低报告等级同格(repo:write);两处都没设时退回这个仓库生效模型组合的第一个 Reviewer。基点探索与知识整理的发起表单不再选模型,只读显示生效的那一处;反哺不再看探索记录。合并 agent 随轮次开跑冻结它,知识任务在发起时读一次。

## Considered Options

- **分两个槽:合并模型与知识任务模型各一处。**合并要的是「读得懂几段说法并合成一段」,知识任务要的是「读代码推规则」,能力要求确有差别。但两者今天都落在同一个退路上(组合第一个),分槽后多一处要人决定的东西,而实例里能选的模型就那几个;真要分开时再拆,拆的代价是一列一控件。
- **只收知识任务,合并 agent 继续隐式。**合并 agent 的取法本来没有界面,看起来不算「散落」。但它是「组合第一个」这条规则的唯一剩余用户,留下它就留下一条只有读代码才知道的模型来源。
- **不加槽,发起时仍现场选。**保住每次探索都能换模型的灵活性,代价是「选模型的地方只有两处」不成立,反哺跟着上次探索走这条隐式规则也留下。

## Consequences

- CONTEXT.md 新增「辅助模型」词条;审查策略、思考档位、综合说明、基点探索、知识整理、人工提议六个词条改口。
- 旧的探索记录里的模型只剩历史意义,不再决定任何后续任务用什么模型。
- 只持 knowledge:write 的角色以后选不了知识任务的模型;要换模型得找持 repo:write 的人改仓库配置。
- 退路取生效组合第一个,仓库改了模型覆盖就可能连带换了合并与知识任务的模型;要稳住就显式设辅助模型。
- 同一批决定:审查策略与仓库配置各整页一个保存、一个版本号,上限项与报告等级可空即跟随系统默认;ADR 0010 里「分别保存、各自带版本、显式区分来源」那一句由此作废,已在该 ADR 加附记。
