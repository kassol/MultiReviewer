# 读范围由仓库分配决定,权限格只管写与动作

面板原来用两个读权限格 `repo:read` 与 `review:read` 决定谁能看评审记录、仓库与处置率。它们只有开和关两档:一个人要么看全部仓库,要么一个都看不到。按项目把仓库分给具体的人,这两格表达不了。ADR 0018 之前的一票(#191、#192)已经引入仓库分配:分配挂在用户上,服务端在鉴权之后统一按它收窄列表、按它把分配外的目标判成 404。分配落地之后,这两格再没有能独立回答的问题——它们只能在「已经按分配收窄过的那份数据」之上再加一道全有全无的开关。

因此:读评审记录、仓库与处置率登录即可,读得到哪些完全由仓库分配决定;权限格只表达写与动作。`repo:read` 与 `review:read` 从 `PANEL_PERMISSIONS` 删除,原来声明它们的路由改为 `authenticated-only`,`isPanelPermission` 对这两个字面量返回 false,角色写入带它们回 400。`model:read` 与 `credential:read` 不动:模型服务与凭据不挂在仓库上,分配管不到它们的可见性。

## Considered Options

- **两格保留,与分配相与。**一个人要能看评审记录,既要有 `review:read`,又要分到仓库。两处都要维护,而少了任何一处结果都是「什么都看不到」;实际使用里第一件事永远是把这一格加满,它只剩一个多余的失败模式。
- **两格改成「看全部仓库」的越权格。**表达力确实多一档,但它与「系统管理员不受分配限制」重合;真需要看全部的人就是系统管理员。
- **四个读格全删,`model:read` 与 `credential:read` 一并去掉。**模型凭据是全局资源,没有分配这一层去接管它的可见性;删掉就等于凭据对所有登录用户可见。

## Consequences

- 权限格从 10 格降到 8 格。角色矩阵少两行,升级时角色里的这两种行在建 schema 时删掉(库里的 `user_version` 被模型服务迁移器独占,这一步做成幂等的删除,不占版本号)。
- 隐含关系只剩 `model:write` → `model:read` 与 `credential:write` → `credential:read`;`repo:write` 不再隐含任何读格。
- 前端 `homeFor` 简化成「登录就落首页」:再没有「有这一格没那一格」的分流。零权限说明页删除——没有权限格的账号照样看得到评审记录,该说明的是「没分到仓库」,那一档由首页的零分配空态承担。
- 一个没有任何角色的账号能读它分到的全部仓库。给人开账号这件事从「建账号 + 配角色」变成「建账号 + 分仓库」,只有需要写或动作时才配角色。
- 读接口的 403 这一档消失:未登录 401,分配外 404,再没有「登录了但没这一格」。
