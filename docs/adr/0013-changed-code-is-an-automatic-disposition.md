# 代码已改动是一种自动处置

ADR 0006 把 resolve 定义为「人看过并做了结论」,并明确它证明不了问题被修复。范围审查引入比较项推进后,作者最常见的动作是改代码再推进,而不是回到 Finding 上点 resolve;按 0006 的口径,这些被修掉的 Finding 会在审查完成时全部按未处置计入分母,处置率会系统性偏低。因此新增一种自动处置:新一轮 Review Run 发现某条 Finding 所指代码已改动(它的内容指纹在新比较项上算不出)且本轮未再报出时,MultiReviewer 自动 resolve 该评论,处置值记为「已改动」,与人工 resolve 分开存储与统计。人已作出的处置一律不被自动处置覆盖。该规则同样适用于 PR 触发的 Review Run,两条链路一套代码。

## Considered Options

- **不自动处置,面板标出「代码已改」等人点。**保住 0006 的口径,但把最高频的动作留给人做,与「操作尽量在面板一次完成」的目标相反。
- **自动 resolve 且与人工 resolve 同值。**最简单,但处置率从此分不清「人看过」与「代码改过」,面板存在的理由(多模型选型)就失去了那个最有信息量的维度。

## Consequences

- 指纹仍算得出但本轮未再报出的 Finding 不动:那是模型的波动,不是代码的改动。
- 「已改动」写回 Forge 的仍是同一个 resolve 状态;Forge 上看不出两种处置的区别,区别只在本地库与面板统计里。
- 人可以把「已改动」改回未处置,此后它就是人工处置,自动规则不再碰它。
- 处置率的分子可以按人工与自动分列;0006 的「resolve 衡量人看过」口径只对人工处置成立。
