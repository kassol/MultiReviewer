# 模型服务配置先于审查策略

模型服务是 provider、调用目标、模型凭据与模型来源的唯一配置边界；审查策略只引用已经可用的模型标识。两者继续分页面，但组成一条连续任务：操作员先完成模型服务配置，再明确选择 Reviewer，最后注册仓库。

## Decision

- 添加与修改模型服务共用独立的三步流程页：选择来源、配置并执行模型发现、明确选择或手填验证模型并执行最小真实推理。候选配置只留在页面内存；最终提交重新发现并验证，成功后按模型服务版本原子切换，失败不改变当前版本。手填模型验证成功后成为模型补录。
- 创建模型服务成功后进入审查策略并定位新服务，但不自动修改全局模型组合；修改既有服务成功后返回服务概览。模型服务详情分成概览、维护、模型三页签，概览先回答能否运行以及被哪些组合引用。
- 全局模型组合完成首次配置后必须非空。编辑时可以出现空草稿，保存时必须至少有一个可用模型。模型组合与分批上限分别保存并各自带版本；分批上限显式区分系统默认与自定义值。分批上限现在是每批改动行上限与每批文件数上限两项，任一超限即另起一批；批次并发数与它们同形，也是一项独立保存、独立带版本的全局设置。
- 审查配置就绪前不允许注册新仓库。面板用全局检查单串起添加模型服务、保存审查策略与注册首个仓库，实例启用后自动隐藏。历史空组合保留为未就绪状态；已有仓库的投递继续留下明确失败记录，直到管理员补全策略。
- `repo:write`、`model:write` 与 `credential:write` 各自包含同资源的读权限。只读用户看到静态配置，写操作不渲染。
- 迁移保留的名字冲突服务通过原子改名恢复：新名称验证成功且全部被引用模型可用后，在同一事务中迁移模型服务、全局模型组合与模型覆盖；任一引用模型缺失则整次不变。

## Consequences

模型服务配置和模型选择不会重新形成两条写链。模型发现失败不再迫使操作员提前猜验证模型，也不阻止支持真实推理但没有可用模型清单的 OpenAI-compatible 端点。配置流程中的长操作会显示阶段并暂时锁定离开；未提交修改离开前确认丢弃，模型凭据不进入浏览器持久存储。面板只返回安全的失败摘要与 request id，原始异常留在服务日志。

本 ADR 保留 ADR 0008 的凭据加密、只写不回显与子进程隔离决策，并取代其“凭据独立保存后到 Review Run 才发现不可用”的生命周期。本 ADR 保留 ADR 0009 的厂商目录来源与补缺优先级，并取代其中把 `models-store.json` 当作面板与 Reviewer 共用当前配置的结论；数据库中的模型服务版本与目录快照是当前事实。
