# 会话基点由人更新,更新即回收子进程重建

Agent 会话按仓库记下会话基点,工作树按它检出,空闲回收后重备仍停在同一个 commit(ADR 0033 的后果)。分支往前走了,会话读的仍是建时那份代码,要读新代码只能新建会话或重梳,之前谈过的都得重来。

选定的做法:**人在空闲的会话里按仓库把会话基点换成它记下的那条分支此刻的 head;更新落一条「基点更新」会话记录,然后回收子进程,下一条消息按记录惰性重建。**分支 head 仍经 `defaultBranchHead` 同一处解析语义(先同步远端、分支没了就报错不回落)。来自 Tag 的会话基点没有「最新」,不能更新;会话基点因此要记下来源种类。已有的记录与产出一律不改,「基点更新」那一条就是序列里新旧代码的分界。

## Considered Options

- **保留子进程,只换工作区,再注入一条消息。**省一次重建,但系统提示里的短 sha 仍是旧的,agent 要靠注入的那句话推翻自己已读进上下文的代码;重建走的是空闲回收已经在用的那条路,系统提示、仓库清单与那条记录一起从头对齐,不加第二套机制。
- **重开选基点弹窗,能换分支、换 Tag。**它就是重梳那一档的能力;会话中途换到另一条线上的代码,之前的记录与产出说的就不是同一个仓库的同一条线了。「更新」限定为同一条分支往前走,边界才说得清。
- **运行中也允许,排到队列里。**子进程正在读的工作区不能换,只能多一档队列项等回合边界;空闲才允许把这一档整个省掉,人等它空闲再点。
- **给旧产出打「基于旧 commit」标记。**产出记着产生它的那次工具调用,序号已经排在那条记录之前;再加一格标记是把同一件事记两遍。

## Consequences

- CONTEXT.md 新增「会话基点」「更新基点」「基点更新」三条。
- 会话基点多一格来源种类(分支或 Tag);这一记录之前的存量会话缺这一格,读作分支——点更新时分支解析失败就照 ADR 0033 报错,不猜。
- 更新与发消息同一权限格:能对这个会话说话的人就能让它读新代码。
- 更新回不到旧 commit;面板上先确认一次,写明仓库、分支、旧 sha 到新 sha,以及下一条消息会重建会话。
