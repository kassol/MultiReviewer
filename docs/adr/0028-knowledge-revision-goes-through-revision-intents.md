# 知识修订只经修订意图与裁决,人不手写陈述

知识集的四个直改面——新增条目、修改条目、草案手填新增、草案逐条修改——加上采纳提案时带改后内容,都让人直接填同一张三字段表:型、陈述、作用范围 glob。这张表对人的要求高得不合理:陈述要合乎陈述形状(ADR 0019 附记,spec #286),glob 要写对却没有校验,型要在规则与事实之间判断;而人手填的条目出处只记 `manual`,当时为什么这么写当场丢失。AI-API 的知识集里 75 条采纳 47 条形状不合格,说明人裁决时几乎不改 agent 的产出,瓶颈在产出形状而不在交互轮数。处置反哺已经是一条完整的「人写意图、agent 产出、人裁决」管线:备注原文、Finding 位置、现集与待裁决队列交给 agent 单轮产出,经共用映射入队。

选定的做法:**知识集只由裁决与直接废止改动,人从不手写陈述、型与作用范围。**四个直改面与改后采纳一并撤掉,端点删除;直接废止条目与删除草案条目保留,它们写不进内容。人写的是修订意图:一段话,说要新增什么、或要把哪条知识条目、修订提案或草案条目改成什么样。修订意图是实体,一行三态(运行中 / 失败 / 完成),带提交人、目标、轨迹、产出与一句收尾;处置备注即一条以那条 Finding 为锚的修订意图,反哺由此获得运行状态。人工提议是出处附注的第四种来源,与另三条链路共用一条 agent 管线:意图、目标及其全部附注、现集、待裁决队列,工作树停默认分支当前 head,模型沿反哺规则。无目标产提案或草案条目,分界与基点探索同;目标为条目产修改型提案,队列里已有指向它的即并入;目标为提案或草案条目原地改写并追加附注。**多轮由提案的附注列表承载**:每一轮都是一次单轮 agent 运行,目标已有的附注全部作为输入,提案加它的附注即修订对话,持久、可回看、重启不丢。

## Considered Options

- **对话式会话:人与 agent 在面板上多轮聊出一条条目。**现有 agent 基础设施只有单轮子进程、面板到 agent 只有单向 SSE、子进程五分钟静默判死,做对话要新建会话对象、双向通道、面向人的超时模型与面板端会话状态机四件东西。它换来的主要好处是 agent 能追问,而追问要求人同步在场,与处置备注「写完就走」的异步用法相反。反哺并入已经证明「同一条提案上再跑一轮、追加一条附注」就是多轮,不必保活会话。
- **保留直改表单作专家通道。**看似无害,实际让「知识集只由裁决改动」这条原则在 API 上说不通,且直改条目继续没有理由可追溯;两条路并存也让 500 字与 100 字两套陈述上限继续并存。撤掉之后陈述上限只剩 agent 那一道。
- **意图不落实体,状态从知识轨迹推导。**轨迹表没有任务行,运行中与失败要靠扫最后一条事件,失败的没法关掉;人提交意图后在等结果,反哺今天「不展示」的形态在这里不够用。
- **废止也走意图。**一次点击变成一次 agent 运行加一次裁决,换来的只是一句理由;要理由的场景处置备注那条链路已经覆盖。

## Consequences

- CONTEXT.md 新增「修订意图」「人工提议」两个词条;知识集版本、知识草案、修订提案、出处附注、处置反哺、知识轨迹、裁决、知识确认八个词条改口。
- 人手填事实型 500 字那道闸(ADR 0020)随直改入口一起消失,陈述上限单一来源:agent 产出 100 字。
- 改写失败没有退路:agent 反复写不出人要的措辞或 glob 时,人只剩驳回与重写意图。缓解是附注的依据格写明假设,让人看得出该改哪句意图。这是要盯的风险。
- 意图运行不受基点探索与知识整理的互斥限制,各派自己的工作树;同一目标同时只跑一条,落地时目标不在待裁决即改判失败并留原因。
- 存量 `manual` 出处的条目原样保留。
