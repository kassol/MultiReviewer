## Platform

web

## Users

主用户有两类，共用这一套面板，不拆成两个产品。

- **操作员**：部署并管理 MultiReviewer 的人。配置模型服务与审查策略、注册仓库、轮转 Key、核对 hook、看 Review Run 是否在跑。
- **团队负责人**：看处置率与模型表现，判断哪家 Reviewer 值得留。不负责日常配置，但会常来这一面。

打开面板时第一件必须做成的事是确认**服务健康**：审查在跑、hook 没漂、模型能运行。配置与质量观察排在健康之后。登录后落到评审记录（`/runs`），不再落到仓库。健康信号只留在相关页：Run 失败在评审记录，hook 在仓库，模型运行能力在模型服务页。实例尚未启用时，全局检查单串起模型服务、审查策略与首个仓库。一天打开几次，密度按扫读来。

## Product Purpose

MultiReviewer 对 pull request 做多模型并行代码审查。审查挂在 Gitea 的 PR 上，以行级 review 评论呈现。

这套面板是服务的操作面与观察面。Gitea 只给人看评论；面板回答服务本身是否健康、配置是否齐、审查质量是否站得住。成功的标准是：操作员一眼能判断该不该动手，负责人一眼能判断哪家模型在产出可处置的 Finding。

## Positioning

这是唯一能把「审查机器的健康」和「Finding 的处置」放在同一处看见的界面。Gitea 看不见 hook 代次、模型服务状态、缺席 Reviewer 和按 Finding Identity 折叠的处置率；厂商控制台看不见本服务的仓库准入与 Review Run。

## Operating Context

- 目标平台是公司内部 self-host 的 Gitea；开发阶段用 GitHub 作适配层测试，面板准入只有 Gitea。
- 部署形态是 Docker。面板与 JSON API 同进程,路径挂在随机的面板前缀下；真正的门禁是本地用户账号、角色权限与会话 cookie。
- 界面语言是中文。领域术语以仓库根 `CONTEXT.md` 为准，代码、文案、沟通用同一套词。
- 日常场景是内网桌面浏览器；窄视口要可用，但不是主要工作面。

## Capabilities and Constraints

产品能力：

- 登录：本地用户名与密码换落库会话；零用户时用启动日志里的 bootstrap 口令注册第一个系统管理员。
- 仓库：搜索注册、移除、Key 代次与核对 / 轮转、每仓库模型覆盖、从仓库详情重跑指定 PR。
- 评审记录：跨仓库 Review Run 时间流、部分失败可见、逐条重跑。
- 处置率：模型 × 分类矩阵，口径是 Finding Identity，每格带分子分母。
- 模型服务：按 provider 管理调用目标、模型凭据、模型发现与模型补录；模型凭据只写不回显。
- 审查策略：管理全局模型组合与分批上限；仓库可以用模型覆盖替换全局模型组合。
- 首次配置：全局检查单串起添加模型服务、保存审查策略与注册首个仓库。

技术约束：

- 现有栈：Vite + React 19 + TanStack Router/Query + Radix Themes / Primitives / Icons + Tailwind v4。cmdk 与 react-day-picker 分别保留搜索组合框和日期范围行为。构建产物经 `/assets` 提供，产物不得含面板前缀。
- 只做亮色一套（issue #46）。
- 前端不做程序化测试（issue #26）；逻辑压在服务端契约上。
- 通用组件外观由 Radix Themes props 与 token 提供；Tailwind utility 负责页面布局和产品结构；`styles.css` 只放 token 映射与浏览器原生表面规则。
- 不用 `window.confirm`：原生对话框会卡住浏览器自动化。
- Key 与模型凭据的明文从不回显到前端。

已实现的模型配置边界（ADR 0010，2026-08-20）：

- 模型服务配置与模型组合选择继续分属两个页面，创建成功后直接进入审查策略并定位新服务。
- 模型服务只留一个添加入口；内置与自定义 provider 的创建、既有服务修改都使用来源、模型发现、真实推理三步稳定地址。
- 候选与凭据只留页面内存；未保存离开需要确认，长操作锁住导航。模型发现失败或缺少目标模型时允许手填 model id，最终以重新发现和真实推理决定是否生效。
- 模型服务详情以能否运行为主状态，概览、维护与模型分成三条稳定地址；空且未引用的内置 provider 只留在添加入口。
- 全局模型组合首次配置后必须非空；分批上限放入高级参数并显式区分系统默认与自定义值。

## Brand Commitments

- 产品名：MultiReviewer。
- 现有青色主色（`--primary: #0e7490` 及其衍生）被明确否定，新视觉世界不得沿用它当主色。
- 上一轮收成的「密控制台」视觉被判定为不够产品，本轮是换世界，不是在那套色上再抛光。
- 站在流行产品一侧：手艺上限是 GitHub、Linear、Vercel。熟悉的后台语法（侧栏、页头、表、主按钮），做到这三家的完成度。不发明新交互，不抄任何一家的布局或品牌色。

## Evidence on Hand

- 可运行的六面：登录、仓库、评审记录、处置率、模型服务、审查策略。
- 真实部署数据在 `00-test` 上，含已注册仓库、真实 hook / 代次、Review Run 与处置率。
- 没有品牌手册、摄影、插画或营销文案。后续工作不得编造客户、证言、基准数字或定价。

## Product Principles

1. **先回答健康。** 打开面板，第一眼必须能判断审查在不在跑、hook 有没有漂、模型有没有挂。
2. **两类人共用一面。** 操作员与负责人看同一套页面；用层级把「现在要不要动手」和「哪家模型值得留」分开，不拆产品。
3. **词就是产品。** 文案只用 `CONTEXT.md` 的术语，不另造同义词。
4. **不编造。** 数字、状态、空状态都来自真实 API；缺数据就写清下一步做什么。
5. **亮色、可扫、可对照。** 只维护一套亮色；文字对比度按 WCAG AA。

## Accessibility & Inclusion

WCAG AA：正文与三态色在面板实际用到的底色上对比度 ≥ 4.5:1。
